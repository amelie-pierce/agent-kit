# Global registration: pinned upstream evidence and ownership

This macOS phase registers hook commands and published skills from integrity-locked npm packages plus agent-state hooks generated by the verified Herdr 0.9.3 binary. The npm versions and registry integrity are in [`manifests/npm/package-lock.json`](../manifests/npm/package-lock.json). The kit derives no entry from an existing machine's global configuration.

The pinned `axi-sdk-js` 0.1.13 `dist/hooks.js` in the same lock establishes the AXI SessionStart JSON shape, a ten-second timeout, and the Codex `[features] hooks = true` setting. The kit points commands to the versioned kit npm binaries and adds a `# agent-kit:<tool>` shell comment to identify exactly its own entries. It removes/replaces only entries with that marker whose command points at a release under this kit root. A marked command pointing anywhere else, or with extra keys, is a conflict. Every linked skill must resolve to the installed package's `SKILL.md` before a global write. Removed components lose only their marked hook and kit-owned skill links; the shared Codex feature flag stays enabled, as the upstream AXI uninstaller does.

Claude's [hook reference](https://code.claude.com/docs/en/hooks) documents global `settings.json` hooks. Codex's [hook reference](https://developers.openai.com/codex/hooks) documents `~/.codex/hooks.json`, `config.toml`, and interactive trust review. Codex's [skill documentation](https://learn.chatgpt.com/docs/build-skills) identifies `$HOME/.agents/skills` as the user scope. The kit never writes permission, approval, sandbox, trust, plugin or MCP settings; it does not bypass Codex's `/hooks` review.

The [Herdr 0.9.3 integration guide](https://github.com/herdrdev/herdr/blob/master/docs/versions/0.9.3/website/src/content/docs/integrations.mdx) specifies `herdr integration install claude` and `herdr integration install codex`. The kit runs those integration installers **only inside a fresh disposable HOME**, using the exact verified Herdr binary already installed into this kit root. It checks the generated Claude and Codex script hashes against reviewed 0.9.3 output, copies them to `releases/<release>/herdr-hooks/`, and merges the documented SessionStart entries with kit ownership markers. It does not run Herdr's runtime lifecycle, edit the person's Herdr state, or let the vendor installer touch the person's global agent files. The script hashes and merge code are in [`src/install/hooks.mjs`](../src/install/hooks.mjs). The [no-mistakes setup guide](https://github.com/kunchenguid/no-mistakes/blob/v1.79.0/README.md) says `no-mistakes init` installs its user-level skill. That stays in the person's own repository initialization flow. Firstmate's project hooks already ship in its pinned source checkout.

`plan` and `install --dry-run` list operations and exact values only for kit-owned entries. They do not print unrelated settings, which can contain private values. Installation prints the same preview before the hooks phase writes. Existing JSON files are parsed first and malformed files stop the phase. In `config.toml` only table headers and `[features] hooks` are interpreted; other lines, including quoted project trust tables and multi-line values, are kept byte for byte, and a line the scanner cannot place stops the phase. A refused preview is reported as a `hooks` conflict: `plan` still shows the rest of the plan, and `install` reports the conflict alongside the other phases. Marked hooks pointing at an earlier release under the same kit root are replaced on an explicit release update. Each edited existing file gets a mode-0600 backup under `backups/hooks/` in the private kit root, then an atomic replacement. The receipt records changed files and linked skill targets. Rerunning a matching phase makes no global writes or new backups.
