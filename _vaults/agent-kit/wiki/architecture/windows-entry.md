# Windows entry and WSL2 handoff

Updated 2026-10-27: distribution parsing no longer reads localized words; Linux paths refuse repeated slashes.

Updated 2026-10-27 (Windows readiness): `install.ps1 -DryRun` asks only the root folder, then `windows/agent-kit.ps1 -DryRun` adds `--dry-run` and `windowsSetup` returns `handoff-ready` with the printed `wsl.exe` command instead of spawning it; the guided questions appear only when that command, which carries `--dry-run`, is pasted (windows/agent-kit.ps1:26-29; src/setup.mjs:517; scripts/installer-dry-run-smoke.mjs:25). `setup` bypasses `parseArgs`, so the CLI's Windows-only guard never ran for it (bin/agent-kit.mjs:30; src/kit.mjs:86); `parseSetupArgs` now takes the platform and refuses `--distro` and `--handoff` off win32, and `windowsSetup` passes `'win32'` (src/setup.mjs:48; src/setup.mjs:62; src/setup.mjs:374; src/setup.mjs:501). The saved-channel receipt read goes through `sh -c 'cd; cat -- $1'`, which never expands `~`, so `Get-ReceiptPath` strips a leading `~/` from `--install-root` as well as `--root` (install.ps1:67-76); the Windows CI smoke loads that function from the script's AST and checks both forms under Windows PowerShell and pwsh (scripts/installer-dry-run-smoke.mjs:29-36). Both installers accept only commits on `main`, so the hands-on check in docs/windows-pilot-check.md runs after the release merges (install.ps1:153-154; install.sh:200-201).

Windows has no native install. `windows/agent-kit.ps1` checks Node against the `engines` floor in `package.json`, prints the official download and winget command instead of installing Node, then runs the Node CLI; `-DryRun` turns `install` into `install --dry-run` and refuses `--handoff` as its no-change preview (windows/agent-kit.ps1:20-70). It writes its own messages to stderr so `--json` output on stdout stays parseable.

`inspectWindows` reads the build from `os.release()` (floor 19041), derives the native architecture from `os.machine()` and the `PROCESSOR_*` variables so x64 Node emulated on Arm64 still targets `linux-arm64`, and sets `artifactTarget` so `evaluate` plans Linux artifacts (src/platforms/windows.mjs:57-71; src/platforms/windows.mjs:114-184; src/kit.mjs:94). It runs `wsl.exe` only when `reg.exe query` finds the `WslService` or `LxssManager` service, because the inbox stub can offer to install WSL; then it reads `wsl --status` and `wsl --list` and decodes UTF-16LE with or without a BOM, or UTF-8 (src/platforms/windows.mjs:7; src/platforms/windows.mjs:16-27; src/platforms/windows.mjs:136-147). Header and state words in `wsl --list --verbose` are localized and can contain spaces (German `Wird ausgeführt`), so names come from `--quiet`, running state from `--running --quiet`, and only the `*` marker and trailing version digit are read from `--verbose` rows that start with a known name (src/platforms/windows.mjs:35-50). A version that cannot be read is unknown, not a failure (src/platforms/windows.mjs:168-169). `wsl --status` labels are English-only in the parser, so a localized status leaves the default version unknown; `docker-desktop` distributions are ignored (src/platforms/windows.mjs:29-33; src/platforms/windows.mjs:143). Each gap becomes a step object with the command, whether it needs an administrator PowerShell, and whether Windows must restart; nothing runs it (src/platforms/windows.mjs:109-176; src/install/windows.mjs:60). Terminal, browser and virtualization are advisories (src/kit.mjs:82).

On Windows, `--install-root` and `--firstmate-home` must be Linux paths, absolute or `~/`, from a plain character set, with no empty (repeated-slash), `.` or `..` segments, so `//mnt/c` cannot slip past the check that refuses anything under `/mnt` (src/install/windows.mjs:9-17; src/kit.mjs:61-64). Plans show POSIX paths and skip the global hook preview, which the Linux installer prints inside WSL (src/kit.mjs:135-141; src/kit.mjs:155-181). The handoff argv is `wsl.exe -d <distro> --exec bash -l -c <script> agent-kit-handoff <commit> <root> <home> ...`. The script has no quote characters, so it pastes inside PowerShell single quotes. It fetches the Windows checkout's clean HEAD commit of the kit into `<root>/kit/<commit>` and execs the Linux `install` (src/install/windows.mjs:21-58). `windowsHandoff` validates both paths before inspecting Windows, so a refused path never runs `wsl.exe`. `install --handoff` spawns only that argv; without it the command is printed (src/install/windows.mjs:70-89; bin/agent-kit.mjs:24-30).

Tests mock `reg.exe`, `wsl.exe` and the CIM query, generate `wsl --list` output in English, German and Vietnamese, and run the handoff script with fake `git` and `node` in a temporary HOME (test/windows.test.mjs:1-289). The `windows-latest` job runs a read-only CLI and bootstrap smoke without enabling WSL (.github/workflows/test.yml; scripts/windows-preflight-smoke.mjs:1-56). Real-device behaviour remains **UNVERIFIED**: argument passing through `wsl.exe --exec`, PowerShell 5.1 quoting of the printed command, enablement and reboot, the private repository fetch inside WSL, and the Windows browser opened from WSL. The README keeps the owner's list (README.md:71-82).
