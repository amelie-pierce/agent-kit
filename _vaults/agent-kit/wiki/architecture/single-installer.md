# Single installer and guided setup

`install.sh` is deliberately thin. It checks the person-installed floors (copied from the manifest, and a test keeps them equal), Homebrew and the Xcode Command Line Tools on macOS, and `gh auth status` by exit code only (install.sh:16-18; install.sh:84-117; test/install-sh.test.mjs). It resolves the channel to a full SHA. `releases` is the newest `main` commit that changed `manifests/pilot-skeleton.json`; `main` is its head. The SHA must compare as `ahead` or `identical` against `main` (install.sh:141-153). The kit is fetched into a temp folder with a one-shot `credential.helper=!gh auth git-credential` and an empty global git config, then handed to `node bin/agent-kit.mjs setup --kit-dir --kit-commit` (install.sh:155-170). `--kit-dir` replaces the fetch with a local clean checkout for development and CI.

Because a release is a manifest-changing merge, the installer needs a manifest change to be reachable on the default channel. A kit commit without `src/setup.mjs` is refused with a pointer to `--channel main` (install.sh:162). The release label moved to `macos-pilot-3` for that reason; pins did not change (manifests/pilot-skeleton.json:3).

`setup` (src/setup.mjs:359) asks for the root first; `--root` skips that question. It derives `<root>/firstmate`, `<root>/.tools`, the `<root>/.treehouse` pool, `<root>/.zoe-fleet` tower state and the wrapper path. `--install-root` and `--firstmate-home` are conflict-checked overrides (src/setup.mjs:109-121). `checkRoot` hard-refuses the home directory, its ancestors, system locations, `/mnt` inside WSL, ancestors holding `fm-bootstrap.sh` or `.git`, a non-empty `firstmate/`, and a non-empty `.tools/` without a receipt. It returns confirmation reasons for another Firstmate home or other files (src/setup.mjs:79-107). The existing Firstmate-home rule needed no relaxation, because `firstmate/` and `.tools/` are siblings (src/install/macos.mjs:179-190).

Answers come from flags, then saved receipt answers (unless `--reconfigure`), then prompts, or defaults under `--yes` (src/setup.mjs:185-242). Prompts read lines from any stream, so tests script stdin (src/setup.mjs:123-160). The shared `evaluatePlan` serves check and plan with `withTower`, `globalHooks` and `towerState` options (src/kit.mjs:201-203). Setup gates only on failed required prerequisites (src/setup.mjs:274-277). It prints the summary and writes nothing before an explicit yes (src/setup.mjs:244-272).

Seven steps are recorded under `receipt.setup.steps`: kit copy, tools, Treehouse wrapper, git identity, starter mate, sign-ins, doctor (src/setup.mjs:20-28; src/setup.mjs:436-458). The receipt also carries `setup.answers`, `setup.paths` and `setup.kit`. `resumeSummary` names the first step that is not complete. Every step is idempotent and re-verifies on rerun; `installPlatform` skips digest-matched phases, so nothing is downloaded twice (src/setup.mjs:174-183). A different receipt release stops with a pointer to `update` (src/setup.mjs:381-386).

The Treehouse wrapper exports `TREEHOUSE_ROOT=<root>` and execs the versioned kit binary; Treehouse's `--root` still outranks it, which Firstmate relies on for second-mate pools under XDG state (src/setup.mjs:300-323; pinned Firstmate `bin/fm-wake-lib.sh` `fm_treehouse_home_pool_path`). It is the `treehouse-root` receipt phase, and doctor accepts it as the kit `treehouse` on PATH (src/doctor.mjs:94; src/doctor.mjs:124-127). Tower state goes through the launcher's `setup --state`, while its config stays in the XDG location because the launcher has no config override (src/install/macos.mjs:282-294; src/install/macos.mjs:301).

`--harness claude,codex` normalizes to `both` (src/harness.mjs:1-10). The Codex npm phase runs only when the Codex tool is selected (src/install/macos.mjs:520). `--no-global-hooks` skips the hooks phase without removing earlier entries (src/install/macos.mjs:523). The starter second mate runs Firstmate's `bin/fm-brief.sh <id> --secondmate --no-projects` and `bin/fm-home-seed.sh <id> <root>/secondmates/<id> --no-projects` with the filled charter and scope, and never `fm-spawn.sh` (src/setup.mjs:342-357). A real seed against pinned Firstmate is **UNVERIFIED** in tests, which use stub scripts.

On Windows, `install.ps1` fetches the kit the same way into a temp folder and runs `windows/agent-kit.ps1 setup --handoff` (install.ps1:110-118). `windowsSetup` reuses the WSL2 preflight and hands `setupHandoffScript` to `wsl.exe`. The script fetches `install.sh` at the Windows checkout's commit with `gh` inside WSL and runs it with `--commit` (src/setup.mjs:478-515). CI dry-runs both entries against the checkout under review (scripts/installer-dry-run-smoke.mjs). Real-device runs remain **UNVERIFIED**.
